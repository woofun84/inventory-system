# 业务说明

本文按业务模块说明当前系统的操作流程、状态流转与权限口径。成本算法细节见 [成本核算规则](costing.md)，接口清单见 [开发文档](development.md)。

## 1. 角色与权限

### 1.1 角色

| 角色 | 定位 | 权限范围 |
| --- | --- | --- |
| `admin` | 管理员 | 恒定全部权限（不读授权表），含用户管理、备份恢复、清库、成本差异结转、清空日志 |
| `manager` | 主管 | 业务全权：入出库、退货退库、盘点（含过账、更正、作废）、采购（含确认下单、修改已确认单）、物料、供应商、查询、参数设置、日志查询；不含用户管理与日志清空 |
| `operator` | 操作员 | 入库 / 出库 / 退货退库可建档、编辑草稿、过账与查看（`view + manage + post`）；采购可建档、编辑草稿、确认下单与查看（`view + manage + post`）；不能删除整单（`delete`）、不能更正（`correct`）、不能整单作废（`void`）、不能修改已确认单（`modify`）；物料、供应商只读；盘点可建单和录入实盘（`view + manage`），不能确认过账、删除或更正差异 |
| `viewer` | 只读 | 各业务模块 `view` |

权限粒度是「模块 + 动作」。业务单据模块统一使用 `view/manage/delete/correct/void/post`，非单据模块（物料、供应商、参数、用户）维持 `view/create/edit/delete`。各模块与真实操作的对应关系：

| 模块 | 动作 | 对应操作 |
| --- | --- | --- |
| 入库 / 出库 / 退货退库 | `view` | 查看单据、明细与打印 |
| 入库 / 出库 / 退货退库 | `manage` | 建档/编辑草稿：建单、改单头、明细增行/改行/删行 |
| 入库 / 出库 / 退货退库 | `delete` | 整单删除：只删整张草稿单（明细行删除归 `manage`） |
| 入库 / 出库 / 退货退库 | `correct` | 更正整条链路：发起更正、编辑更正草稿、确认更正生效 |
| 入库 / 出库 / 退货退库 | `void` | 整单作废：零行确认，可单独授予，不要求 `correct` |
| 入库 / 出库 / 退货退库 | `post` | 过账：草稿态首次确认过账（已确认后的动作不走此位） |
| 采购 | `view` `manage` `delete` `modify` `post` | 查看；建单/改草稿/明细增删改；删除整张草稿单；修改已确认单（保存后仍为已确认）；确认下单（无更正、作废） |
| 盘点 | `view` `manage` | 查看；建单、生成明细、增删物料行、保存实盘数量（含批量填 0） |
| 盘点 | `delete` `correct` `post` | 删除整张草稿；已确认盘按行更正差异；确认盘点并生成调整（无整单作废） |
| 系统日志 | `view` / `delete` | 查看日志 / 清空全部日志（默认只给管理员） |

`delete` / `correct` / `void` 与 `manage` 刻意拆开，这样把日常建档、改草稿开放给操作员时，不会连带放开删除整单与破坏性操作；`void` 不依赖 `correct`，可单独授予；盘点没有整单作废，已确认单据只能按行 `correct`。采购的 `modify` 只管「已确认单再次编辑」，与草稿的 `manage` 完全分离：有 `manage` 不等于能改已确认单，有 `modify` 也不能改草稿。

### 1.2 服务端校验

- 每个业务路由通过 `requirePerm(module, action)` 校验，内部读 `req.grants`，无权限返回 403。
- 授权以数据库为准：`user_permissions` 存最终授权集合，管理员可在用户管理里按用户勾选，保存即生效；`user_perm_state` 防止「全部取消」在重启后被默认值填回。角色矩阵只提供建号 / 改角色时的默认值。
- `admin` 恒定拥有全部权限，不读取授权表，避免误操作把唯一管理员锁死；用户管理页的 `admin` 行只读。
- 前端 `App.can(module, action)` 只用于控制菜单与按钮显隐，不构成安全边界。
- 权限元数据（模块 / 动作全集、各角色默认值）由 `GET /api/permissions/catalog` 下发；`users` 模块本身不开放勾选。
- 退货与退库是独立模块：采购退货、零星退货、领料退库的读写都只校验 `returns` 的 `view/manage/delete/correct/void/post`，不再叠加 `inbound` / `outbound` 权限；入库 / 出库权限只管各自的普通单据。路由按单据 `txn_type` 自动切换权限模块。
- 系统日志清空由独立权限位 `audit.delete` 控制，默认只给管理员。
- 只授予 `void` 的账号也可发起更正并编辑更正草稿（用于把明细删空后整单作废）；但草稿仍有明细时确认会被 `correct` 拦截。
- 整单删除一律要求草稿态：入库、出库、退货退库、盘点、采购单的 DELETE 端点都先校验单据状态，已确认 / 已过账返回明确错误，前端对不可删除状态不显示删除入口。物料、供应商、参数属于档案数据，没有草稿 / 过账生命周期，沿用各自引用校验（物料被单据或流水引用时拒绝、供应商为软停用、合同被采购单或入库单引用时拒绝）。
- 需要设置-运维授权的操作（备份、恢复、自动备份、清库、成本差异结转）在路由内统一校验 `settings:ops` 授权（admin 默认持有、可单独委派），无授权一律 403，不仅靠前端隐藏按钮。

### 1.3 价格脱敏

`canViewPrice` 由 `price:view` 授权判定（`admin` 恒为真，其余用户按授权表决定），鉴权中间件把结果挂到 `req.canViewPrice`；填/改价格另需独立的 `price:edit`，挂到 `req.canEditPrice`。无查看权限时由**服务端删除键**，各模块口径：

| 场景 | 无价格权限时删除的字段 |
| --- | --- |
| 退货退库列表 / 详情 | `total_amount`、`price`、`amount`、`cost_price`、`cost_amount` |
| 物料台账 | 金额、单价、结存金额、结存均价；金额类排序键回落默认顺序 |
| 成本差异 | `unit_cost`、`avg_cost`、`amount` 及合计金额 |
| 单据查询 / 全局搜索 | 单据 `amount` |
| 领用人查询 | 汇总与明细的 `amount` |
| ABC 分析 | `out_amount`、`share`、`cum_share`、`stock_value`，汇总只保留分类计数 |
| 呆滞分析 | `stock_value`、`avg_cost`，保留数量与天数 |

### 1.4 登录会话

- 同一账号同时只允许一个终端在线。登录成功后在 `user_sessions` 覆盖该用户的 `sid`，JWT 里带同一个 `sid`；先前终端再发起请求时 `sid` 不匹配，返回 401 `SESSION_KICKED`，前端弹窗提示「已在其它终端登录」，不静默跳转登录页。
- 终端标识来自登录页写入 `localStorage` 的 `terminal_id`：同一浏览器的多个标签页共享同一终端，重新登录沿用原 `sid`，不会自己挤自己；换浏览器 / 换电脑 / 手机登录才会顶掉旧会话。
- 前端轮询 `/api/auth/session` 作为心跳，同时刷新 `last_seen`；主动退出只撤销当前 `sid`，旧标签页不会误删新会话。
- `/api/health` 不需要登录，前端用它探测服务器是否可达，断线时显示顶部横幅，恢复后自动消失。

### 1.5 关键字搜索与筛选

- 关键字按空格分词，词间为 AND：一条记录需同时命中全部词；词内不区分大小写，`%`、`_` 按字面匹配，不再当通配符。
- 匹配字段随模块而定，物料维度统一包含编码 / 名称 / 规格 / 品牌：库存查询、物料档案按这四项；单据查询额外匹配单号、对方与明细物料信息；采购列表 / 明细另含采购单号、合同号与供应商；盘点候选按编码 / 名称 / 规格 / 品牌。
- 服务端筛选统一走 `server/utils/search.js`，前端本地筛选（`filterByKeywords`）规则一致：分页列表在服务端筛选，已加载的候选集合在本地筛选。

## 2. 单据状态机

入库单与出库单统一为三态：

```
draft（草稿，可编辑/可删除）
  │ confirm
  ▼
posted（已过账，写入库存流水，不可直接修改）
  │ 作废 / 更正
  ▼
voided（已作废，流水置为 voided）
```

- `draft`：明细行 `status='draft'`，不进入库存与统计；可改行、可删除整单。
- `posted`：明细行 `status='posted'`，生成 `stock_ledger`，库存余额可被查询与核算。
- `voided`：原单保留可追溯，`voided_at` / `voided_by` 记录作废信息；对应流水 `status='voided'`，重算后不再影响余额。
- 已过账单据不允许直接改行，只能走「更正（作废重开）」。
- 建单、改草稿与过账默认对 `operator` 开放；更正重开需要 `correct`，整单作废需要独立的 `void`。过账、更正与盘点确认都在 `BEGIN IMMEDIATE` 事务内先校验状态再写流水，状态已被其它请求改动时返回 `DOC_STATE_CHANGED` / `STOCKTAKE_STATE_CHANGED`，整笔不生效。

盘点单为 `draft → confirmed` 两态；采购单使用 `status` 与 `manual_status`，没有入出库单的作废/更正链。

## 3. 入库

### 3.1 采购入库

1. 新建入库单，选择供应商，可按采购单 / 合同带出待收货明细。
2. 明细行记录物料、数量、单价；可写入 `po_no`、`contract_no`、`order_line_id`。
3. 确认过账后，`costing.postInboundDoc` 生成入库流水，按行价入账并更新移动加权平均。
4. 到货核销优先按 `inbound.order_line_id` 精确匹配采购明细；未关联时回退「采购单 + 物料 + 有效合同号」匹配。双方都带合同号时必须一致，避免同单同料跨合同串账。
5. 供应商与合同号可以在采购单上后补：保存采购单时在同一事务内级联刷新已生成的入库单单头、入库明细、退货单与退货明细（详见 7.4）。
6. 从采购单收货时，若单头未带合同号而全部明细同属一个合同，保存后自动回填单头；跨多个合同时单头保持为空，归属以明细行为准。

### 3.2 零星入库

无采购单 / 合同的直接入库，`txn_type='零星入库'`，来源单位写在 `supplier` 字段。流程与采购入库一致，只是不参与采购到货核销；后续可由「零星退货」按原单退回。

### 3.3 采购退货

`txn_type='采购退货'`，按关联深度分三档，写入 `return_tier`：

| `return_tier` | 含义 | 限制 |
| --- | --- | --- |
| `inbound` | 关联原入库单 | 按原入库行确定可退范围 |
| `po` | 关联采购单 | 按采购单确定可退范围 |
| `contract` | 关联合同 | 按合同确定可退范围 |
| `none` | 无原单退货 | 仅 `admin` / `manager` 可操作，退货原因必填 |

可退数量统计只计入已过账（`posted`）单据，草稿与作废不计。

采购退货按原采购单价冲减库存（流水方向为出库），不重新取移动平均。

界面入口统一为「从原单发起退货 · 采购」：先选原入库单，再带出可退明细；无可退量（未过账或已退完）的原单不进入候选，入口按钮置灰并提示原因。`none` 档保留在服务端供管理员按需调用，页面不再提供无原单的采购退货入口。

### 3.4 零星退货

`txn_type='零星退货'` 落在入库端点，但权限归属退货模块（只看 `returns`），必须关联一张已过账的零星入库单（`return_tier='inbound'`，返回 `ORIGIN_DOC_INVALID` 拒绝其它类型原单）。来源单位不落库，读取详情时从原零星入库单派生；退回数量受原单剩余可退量约束（`RETURN_QTY_EXCEEDED`）。流水方向为出库，单价沿用原入库行。

### 3.5 入库单操作

- 新建：`POST /api/inbound-docs`
- 改行：`PUT /api/inbound-docs/:docNo/lines`（仅草稿）
- 确认：`POST /api/inbound-docs/:docNo/confirm`（`inbound:post`，退货单为 `returns:post`）
- 删除：`DELETE /api/inbound-docs/:docNo`（仅草稿，`inbound:delete`）
- 更正：`GET /:docNo/correction-info` → `POST /:docNo/correction`（需要 `inbound:correct` 或 `inbound:void`）→ 修改明细 → `POST /:docNo/confirm-correction`（有明细需要 `inbound:correct`，零行整单作废需要 `inbound:void`）

确认时的数量口径：`qty=0` 的明细行不生成流水，过账事务内直接删除；若删除后没有有效行，返回 `NO_QTY_LINES`，整单不过账；没有任何明细行则返回 `NO_LINES`。表单保存与确认的行级校验错误会定位到具体行：物料单元格下方显示提示、数量框红框并滚动到视野内，不再只弹整屏 toast。

过账时在同一事务内复核单据状态、可退量 / 超收与库存；并发下单据已被处理返回 `DOC_STATE_CHANGED`，超收未显式确认返回 `OVER_RECEIPT`，单号刚被占用返回 `DOC_NO_CONFLICT`。

## 4. 出库

### 4.1 正常出库

1. 新建出库单，填写领用去向 `destination`、领用人 `receiver`、经手人。
2. 添加明细行；编辑页逐行显示可用量与「参考单价」，数量超出可用量时就地标红。
3. 点确认先做库存预校验：按物料汇总本单数量，与 `stock_balance` 比对，不足时确认弹窗列出「物料 / 需求 / 可用」并禁用确认按钮（`ob_confirm_stock_short`），不再等提交后才报错。
4. 同一弹窗按当前结存均价重算成本，与页面显示金额对比；有价格权限且差异达到 0.005 元时先弹「金额差异确认」，展示重算金额、当前金额与差异，二次确认后才过账。
5. 过账时按当前移动加权平均计价，成本回写到 `outbound.cost_price`，并生成出库流水。

可用库存一律取自 `stock_balance`，不由单据表现算。

### 4.2 领料退库

- 有原单：通过「从原单发起退库 · 领料」选择一张已过账且有可退量的原出库单，自动带出原行与可退量，退库行记录 `origin_line_id`；成本沿用原出库行的实际计价单价。
- 无原单：页面仍保留「新建无原单退库」入口，`origin_line_id = 0`，去向、领用人、退库原因必填；成本按当前均价，当前结存为 0 时回退最近一次正库存均价，从未有过正库存需管理员确认（`NO_COST_BASIS`）。
- 领料退库在出库单上以 `txn_type='领料退库'` 表示，流水方向为入库；确认时同样执行库存与金额差异预校验。

### 4.3 出库单操作

与入库单一致：新建、改行（仅草稿）、确认、删除（仅草稿）、更正重开与整单作废；更正步骤需要 `outbound:correct` 或 `outbound:void`，零行作废需要 `outbound:void`。确认时可用库存与退库可退量都在写事务内复核，不足分别返回 `INSUFFICIENT_STOCK` / `RETURN_QTY_EXCEEDED`；预校验通过但并发下库存已被其它单据占用，仍以事务内校验结果为准。

## 5. 退货与退库查询

`server/routes/returns.js` 提供只读聚合与「原单候选」；写入复用入库 / 出库端点的实现，但权限归属独立为 `returns` 模块（路由按 `txn_type` 切换）：

- `/api/returns/docs`：采购退货、零星退货与领料退库的统一列表，前端分三个页签。
- `/api/returns/docs/:docNo`：单据详情。
- `/api/returns/purchase/origins`、`origin-lines`、`misc/origins`、`misc/origin-lines`：从原单发起时选择原采购入库单 / 零星入库单并带出可退明细。
- `/api/returns/purchase/scope-options`、`scope-lines`：按采购单 / 合同选择退货范围。

前端「退货与退库」页只保留「从原单发起」入口；候选按「已过账且仍有可退量」过滤，没有候选时按钮置灰并说明原因。新建入口只看 `returns:manage`；后端对退货 / 退库单的建单、存明细、过账、删除整单、更正、作废分别校验 `returns` 的 `manage/manage/post/delete/correct/void`，不再要求入库 / 出库权限。

数据来源：采购退货与零星退货取 `inbound_docs`，领料退库取 `outbound_docs(txn_type='领料退库')`。无价格权限时返回前删除金额与成本键。

## 6. 盘点

1. 新建盘点单在弹窗内完成：选择盘点范围（全盘 / 按类别 / 按物料盘点，类别与按物料盘点均可搜索、多选），`POST /api/stocktakes` 在创建事务内直接生成盘点明细并打开右侧录入面板，一步到位。
2. 生成明细：`book_qty` 是创建时刻的账面快照，之后不随入出库变化；范围固化在 `load_scope`，创建后不再提供重载/切换范围的入口。需要补充物料时使用草稿态的「添加物料」（`POST /api/stocktakes/:no/lines`），只做增量追加，不清空已有行与已录实盘。
3. 右侧录入面板顶部动作条常驻：行数、已盘数量、差异数、确认时间（已确认时）、「录入实盘」「只显示未盘」「批量填 0」「确认盘点」。`count_qty = NULL` 表示未盘，`0` 表示实盘为零；改动未提交的行显示「未保存」徽标。
4. 确认：`POST /api/stocktakes/:no/confirm`，需要 `stocktake:post`。确认弹窗先给出差异明细表（物料、账面、实盘、差异），差异行的实盘数量可直接修改；差异按「实盘 − 确认时最新库存」重算，保证确认后账面等于实盘。若盘点期间账面被其它单据改动（创建时快照 ≠ 确认时账面），先返回 `STOCK_CHANGED` 并列出受影响物料，用户确认「以实盘为准」后再带 `force=true` 重试，避免把期间变动一并抹平。系统按最终差异生成 `stock_adjustments` 调整流水，盘盈按回退成本规则计价，盘亏按当前均价冲减。
5. 已确认盘点单可在差异行点「更正此差异」：需要 `stocktake:correct`，填写原因后调用行级更正接口，按新实盘数量覆盖原调整与流水，不新建盘点单；账面与实盘一致时返回 `NO_DIFF`。
6. 盘点确认后不修改入出库单据，库存口径保持「期初 + 入库 − 出库 + 调整」。
7. 草稿盘点单可删除（需要 `stocktake:delete`），已确认不可删除；并发确认冲突返回 `STOCKTAKE_STATE_CHANGED`。
8. 前端权限对应：新建按钮看 `manage`；「录入实盘 / 只显示未盘 / 批量填 0 / 添加物料 / 保存实盘」看 `manage`；「确认盘点」看 `post`；「删除」看 `delete`；差异行的「更正此差异」看 `correct`。盘点没有整单作废动作。
9. 详情卡动作条常驻「打印」（复用通用单据打印），只读输出、有 `stocktake:view` 即可用；输出单头（单号、日期、范围、状态、盘点人、备注）、明细（序号、编码、名称、规格、品牌、单位、账面数量、实盘数量、差异数量，未盘留空）与签字栏（盘点人、复核人、日期），草稿与已确认均可打印。

## 7. 采购管理

### 7.1 采购单

- 一张采购单一行表头，明细在详情页维护。
- 权限口径：`purchase:manage` 放行建单（建单接口可一次性带明细）以及草稿单的明细新增 / 修改 / 删除；已确认单的表头与明细变更走独立的 `purchase:modify`（权限页文案「修改已确认单」），`manage` 不能改已确认单。`purchase:delete` 只删整张草稿单；界面上的「编辑」按草稿 `manage`、「修改」按已确认 `modify`，「确认下单」按 `post` 显隐。
- 修改已确认单：保存后状态仍为 `posted`，不退回草稿、不重新初始化到货进度；供应商、合同号允许改，保存时沿用 7.4 的级联逻辑同步到引用该单的入库单与退货单；价格沿用现有查看 / 填写判定，不新增权限位；单价变更会在同一事务内同步到引用该行的入库单与退货单，并从过账日期起重算结存与后续出库成本（详见 7.6）；改动写审计日志（记录字段与原值 / 新值，单价等价格键对无价格权限的查看者打码），不建版本表。
- 到货保护：已到货的明细行不能移除，订购数量不能低于已到货数量；允许新增行和调高数量，保存后按新数量重算到货进度；已确认单至少要保留一行有效明细（后端返回 `PO_LAST_LINE`）。
- 整单删除只对草稿开放：已确认的采购单不能删除（返回 `PO_NOT_DRAFT`），前端在已确认单据上不显示删除入口；已有过账入库记录的采购单即使处于草稿也会被拒绝。
- 单号由 `docno.genDocNo('po', date)` 生成，前缀可在参数设置中修改。
- 供应商与合同号允许后补：新建时可为空，保存时在同一事务内级联同步到已生成的入库单、入库明细、退货单与退货明细（见 7.4）。
- 到货状态由明细汇总：`无明细 / 未到货 / 部分到货 / 已到货`；`manual_status` 可置为 `已关闭` / `已取消`，优先于自动状态。
- 逾期天数按 `expected_date` 与当前日期计算，只对未到货 / 部分到货生效。
- 单价输入统一保留两位小数（`fmtPrice2`），避免浮点尾数写回；保存时订购数量不能小于已到货数量，命中时前端按 `line_id` 定位到具体行做红框与行内提示（`PO_QTY_BELOW_RECEIVED`）。

### 7.2 合同

- 合同是独立档案，采购单与合同为多对多。
- 真实归属以 `order_lines.contract_no` 为准，采购单头的 `contract_no` 只是新建明细时的默认值。
- 明细引用不存在的合同号时自动建档（`ensureContract`），保证按合同查询不漏单。

### 7.3 采购明细与到货履历

- 采购明细支持按采购单、合同、综合三个入口查询。
- 每行可下钻到入库履历，显示已到货数量、未到数量、行状态与逾期天数。
- 单据级「关联入库单」采用并集归属：单头匹配或任一明细行匹配都算；数量金额只汇总属于本采购单 / 合同的明细行，草稿与作废单据同样返回，由前端按状态徽标区分。

### 7.4 供应商 / 合同号后补的级联同步

采购单保存时，若表头或明细的 `supplier` / `contract_no` 发生变化，`cascadePoRefs(poNo)` 在同一事务内按四步刷新下游：

1. 归属该采购单的入库单（单头 `po_no` 命中，或明细行 `order_line_id` 命中）刷新单头 `supplier` / `contract_no`；
2. 入库明细按 `order_line_id` 对齐采购行的 `contract_no` 与 `po_no`；
3. 引用这些入库单的退货单从原入库单回填单头；
4. 退货明细按 `origin_line_id` 从原入库行回填。

供应商按采购单当前值原样同步（清空也同步，避免残留旧值）；合同号只在采购单有值时覆盖，避免把行级单独指定的合同清空。

### 7.5 供应商档案

- 供应商支持软停用：`status='disabled'` 后不再出现在新单据候选里，但历史单据与采购明细仍保留原值，可随时重新启用（不物理删除）。
- 供应商下拉统一取自 `GET /api/suppliers/options`：包含在用档案、停用档案与历史单据中出现过但档案缺失的值；停用项标「已停用」，仅存在于历史单据的值标「历史值」。
- 新建 / 编辑采购单、采购收货入库、退货等页面的供应商输入共用同一份数据源，避免各页各查一套导致候选不一致。

### 7.6 采购补价与成本重算

采购单价允许后补。入库单可以 0 单价过账，按 0 成本入账，**不拦截空价过账**；之后主管在采购单「修改」页直接改明细行单价（该页面本就允许同时改数量与单价），保存即触发下游同步与成本重算。不新增入库页补价入口，也不新增独立权限位，沿用现有价格查看 / 填写判定。

保存已确认采购单时，同一事务内执行 `syncPoPriceChanges`：

1. 找出 `order_line_id` 指向被改价采购行、状态为 `draft` / `posted` 的入库明细（排除采购退货 / 零星退货行）；
2. 草稿入库单直接改 `inbound.price`（`amount` 为生成列，自动跟随），不产生流水、不重算；
3. 已过账入库单先改业务行单价，再把对应 `stock_ledger` 行的 `unit_cost` 原地改为新价，从该物料在该单的最早核算序号起重算（`costing.updateInboundPrices` → `recomputeFrom`）。价格不改变数量与核算顺序，因此不重排序号；
4. 重算顺带刷新后续出库的实际计价（回写 `outbound.cost_price`，`cost_amount` 生成列跟随）与 `stock_balance` 快照，保证结存数量不变、结存金额与单据金额一致；
5. 引用被改价入库行的退货明细（`origin_line_id` 命中，状态 `draft` / `posted`）跟随改为新单价，已过账退货单同样从自身核算位置重算，状态保持 `posted`。

口径说明：`po` / `contract` / `none` 三档退货不绑定具体入库行，可能跨多个入库价，单价由退货单自身确定，因此不随采购单改价自动覆盖。退货档 `inbound` 受「退货单价必须等于原入库行单价」约束，改价时原单与退货单同步更新，避免确认时命中 `RETURN_PRICE_MISMATCH`。

保存响应带 `price_sync`（`synced_docs` / `recalculated_docs` / `synced_returns` / `recalculated_returns`），前端提示「已同步 N 张下游单据，其中 M 张触发成本重算」。

审计：每次改价写两条留痕——

- `audit_logs`（`module='purchase'`、`action='price-recalc'`）：单据、字段（单价）、原值、新值，以及同步 / 重算的单据清单与重算后结存；价格键对无价格权限的查看者按 `maskRowDetail` 打码；
- `inventory_recalc_logs`：每条受影响物料一行 `kind='price-recalc'`（重算前后结存、起止序号、影响行数）；后续出库成本被改写时另记 `kind='cost-change'`。

不做历史数据回填，也不做旧库兼容。

## 8. 参数设置与运维

### 8.1 基础参数

- `GET /api/params` 返回类别、单位、去向、单据编号规则；货币恒为 `¥`，不可改。
- 领用去向未配置时，接口返回内置常用项（生产领用 / 工程领用 / 维修 / 报废）并标记 `builtin`，不写库；一旦用户自行配置任意去向，内置项立即失效，以配置表为准。
- 类别 / 单位 / 去向支持新增与删除。删除前做引用校验：类别 / 单位被物料档案按名称文本引用、去向被出库单按名称文本引用时，删除会被拒绝（409 `PARAM_IN_USE`，返回引用条数），需先修改这些记录；无引用才按 id 删除。是否存在引用按名称文本精确匹配，历史单据的旧文本不在校验范围内。
- 单据编号规则：`{前缀}-{日期段}-{序号}`。日期段可选完整 `YYYYMMDD`（默认，历史行为）或仅年月 `YYYYMM`，切换只影响之后生成的新单号，历史单号不变。前缀限大写字母 / 数字、长度 1–8 且互不重复，序号位数 1–8。默认前缀：`GRN` 采购入库、`RET` 采购退货、`RTS` 零星退货、`GIN` 正常出库、`GIT` 领料退库、`ST` 盘点、`PO` 采购单。设置页可实时预览各类单据的下一号（按候选前缀 / 位数 / 日期算真实下一号，不写库）。

### 8.2 备份与恢复

- 备份下载：默认生成 `.zip` 备份包，内含 `inventory.db`（`VACUUM INTO` 一致性快照，含 WAL 未 checkpoint 的已提交数据）、`images/` 物料图片与 `manifest.json`；文件名带时间戳，默认写入 `backups/`。也兼容直接下载旧版 `.db`。
- 自动覆盖式备份：管理员在参数设置里选择每小时 / 每天 / 每周（每天、每周可指定时刻，每周可指定星期），设置存 `params.auto_backup`，重启后仍生效。运行状态（最近执行时间 `last_run_at`、最近错误 `last_error`）单独存 `params.auto_backup_state`，与配置分离，避免每次备份覆写配置；读时兼容旧版本把状态混在配置里的格式。每次执行覆盖同一份 `backups/auto-backup-latest.zip`，不堆积历史文件；停机期间错过的周期会在启动后补跑一次。也可随时「立即备份」。
- 恢复：上传 `.zip` 或旧版 `.db`。先校验「表集合、列名集合、列声明类型」与当前版本一致；`.zip` 还会校验包内清单与图片路径，`.db` 若引用了图片则要求改用备份包。通过后自动备份当前库、替换库文件并同步物料图片目录。确认短语为 `恢复`。结构不一致的旧版本备份会被直接拒绝（`BACKUP_SCHEMA_MISMATCH`）；`user_sessions` 不参与结构比对，旧备份不含该表时按空会话恢复，需要重新登录。
- 清业务数据：保留物料、供应商、用户、用户级权限、参数、类别、单位、去向与物料图片，清空单据、流水、余额、盘点、成本差异与审计日志，随后按物料档案重新生成期初流水，并补写一条本次清库记录。确认短语为 `清空`。
- 全部清空：在清业务数据基础上再删除物料、供应商、合同、用户、用户级授权与登录会话，同时清理物料图片，重建默认管理员。除确认短语 `全部清空` 外，还须输入当前管理员账号密码二次校验（错密码 403 `PASSWORD_MISMATCH`、未填 400 `PASSWORD_REQUIRED`），防止他人趁会话未锁执行不可逆操作。
- 危险操作前都会自动快照当前库，响应返回备份文件名；操作完成后补写一条审计记录。

### 8.3 成本差异结转

`POST /api/settings/cost-variance/settle`（仅 `admin`）把 `cost_variances` 中 `status='open'` 的记录批量置为 `settled`，写入结转批次与时间。结转只改状态，不动库存数量、金额与均价。

### 8.4 物料档案的唯一性与期初锁定

- 「类别 + 名称 + 规格 + 品牌」四字段唯一（比较时去首尾空格、忽略大小写，空值按空串）。保存时先查重，命中返回 `MATERIAL_DUPLICATE`；编码重复返回 `MATERIAL_CODE_EXISTS`。建索引前若库里已有重复组，服务启动会直接阻断并列出冲突记录，不静默合并。
- 期初数量 / 单价在保存物料时即写入期初流水（业务日期 `1970-01-01`），不再依赖重启补账。物料一旦有期初以外的流水，期初字段即锁定，再改返回 `MATERIAL_OPENING_LOCKED`，避免倒挂历史成本。

### 8.5 系统日志

- 拥有 `audit.delete` 的用户可在系统日志页「清空全部日志」，该动作默认只给管理员。清空在同一事务内先删除全部记录，再补写一条本次清空记录（含删除条数），保证「谁在何时清空了日志」仍可追溯。
- 「对象」列写业务名而不是原始键：参数类日志写成「参数：类别-名称 / 参数：单号规则-采购入库」，单据类日志保留单号；枚举值按同一套中英映射翻译，历史记录缺结构化数据时回退到模块 + 动作生成的摘要，不再直接展示原始 JSON。
- 日志详情按结构化 `detail_json` 渲染为中文摘要与字段标签；数组值按「n 项」折叠，不再输出占位符。

### 8.6 物料档案维护

- 物料图片：新增 / 编辑物料时可上传图片，前端先压缩再上传；文件保存在 `uploads/materials/<物料id>.<ext>`，不写数据库，替换时清理旧后缀文件。仅接受 JPEG / PNG / WebP（按文件魔数判断，拒收 SVG），单文件上限 300KB；图片接口按物料编码读取，删除物料时同步清理。
- 列表筛选：支持关键字、类别、状态（在用 / 停用）与库存状态（正常 / 补货 / 缺货）组合筛选；库存状态按当前结存与 `min_stock` 计算。
- 批量新增：弹窗内可增删行，也可从 Excel 复制区域直接粘贴；编码留空按类别前缀自动生成，类别、名称、单位必填，同一批内与库内都按四字段查重，单次最多 500 行，校验不通过整批不写入。
- 批量导入：仅接受 CSV（UTF-8 / GBK / GB18030 自动识别，兼容 Excel 导出的 ANSI 中文），`.xlsx` / `.xls` 会提示先另存为 CSV；先解析预览并逐行标注错误，确认后一次性写入，全部成功或全部回滚。类别 / 单位下拉可搜索；供应商下拉同样支持搜索并标记停用 / 历史值。
- 物料编码修改会级联更新引用该编码的单据与流水，避免留下悬空编码。

## 9. 查询中心

查询中心由 `public/js/07-stock.js` 实现，四个板块共用详情卡骨架与打印 / 导出能力。

### 9.1 库存查询

- 列表数据来自 `GET /api/stock-summary`，支持关键字、类别、库存状态筛选；无价格权限时不返回金额与均价。
- 库存状态：缺货、补货（低于 `min_stock`）、正常、停用。
- 右侧物料详情卡：基本信息 + 库存流水。流水来自 `GET /api/ledger/:code`，支持分页、业务类型、出入方向、日期区间、是否含作废、排序；金额类排序在无价格权限时回落默认。
- 支持导出 CSV 与打印，导出内容与当前筛选、排序一致。
- 列表滚动时列标题吸顶，分页器在内容超出一屏时贴底常显；内容不足一屏时随内容排在末尾，不悬浮。单据查询、领用人查询与各单据列表共用同一套做法。
- 四个板块的分页统一夹住越界页码：总数变化或连续点击时最多停在最后一页，不会进入空白页。

### 9.2 单据查询

- 列表来自 `GET /api/query/docs`，是入库单与出库单的并集视图，支持单号 / 对方 / 日期 / 状态 / 来源筛选与排序。
- 详情卡页签：基本信息、单据明细、关联单据；只读渲染，不提供编辑入口。
- 支持导出 CSV 与打印。

### 9.3 领用人查询

- 列表来自 `GET /api/query/receivers`，口径为「正常出库 + 已过账 + 有领用人」。
- 净领用 = 正常出库数量 − 已过账领料退库数量（按原出库行的领用人归集）。
- 详情 `GET /api/query/receivers/:name`：汇总、单据清单、物料构成；金额仅在 `canViewPrice` 时下发。
- 支持导出 CSV 与打印。

### 9.4 库存分析

- ABC 分类：区间净出库成本降序累计，加入本行前累计占比 < 70% 为 A、< 90% 为 B，其余为 C；区间内无出库但有库存归 `N`（无出库）。
- 库存周转率：区间净出库成本 ÷ 区间平均库存金额；平均库存金额按每日结存金额算术平均（逐日回放有效流水）。
- 呆滞分析：结存 > 0 且距最后一次正常出库超过阈值（默认 90 天）；从未出库时用最后流水日期兜底，无任何流水标记为 `never_out`。
- 预警清单可跳转到库存查询并按物料编码打开详情卡。

### 9.5 全局搜索

`GET /api/query/search` 跨物料、单据、领用人三组返回轻量结果，默认每组 5 条、最多 10 条。物料排除停用；单据复用查询中心并集口径；领用人只返回姓名、单数、最后日期。无价格权限时不下发金额。

## 10. 作废与更正重开

- 作废：已过账单据可作废，单据状态置 `voided`，对应流水置 `voided` 并触发重算，原单信息保留可追溯。作废在界面上通过「发起更正后把明细全部移除、再零行确认」完成，后端按草稿明细数判定动作：零行需要 `void`，有明细需要 `correct`。
- 更正重开（修订号）：
  1. 读取更正信息 `GET /:docNo/correction-info`；
  2. 创建更正单 `POST /:docNo/correction`（需要 `correct` 或 `void`），原单作废，新单号沿用原单前缀与日期段并追加 `-R1`、`-R2`……修订号不占用正常流水序号；
  3. 在更正单上修改明细（保存明细按 `correct` 或 `void` 任一放行）；**仅零星入库**的更正草稿，明细单价在账号具备价格填写权（`price:edit`）时可改；采购入库、采购退货、零星退货的更正单价一律只读（沿用原行价 / 来源价），领料退库的出库更正单价来自原出库单、同样只读；
  4. `POST /:docNo/confirm-correction` 过账：有明细走 `correct`，零行走 `void`。
- 零星入库更正改价与改量走同一条链路：新单按更正后的单价进成本流水，并在原单的核算位置重新入账、重算该物料此后的全部流水（后续出库成本随之刷新），结存数量不变、金额与均价按新价重算。审计记录变更前后的单价（`price_changes`）、重算后的结存（`balance_after`）与同步的退货行数（`synced_return_lines`）。
- 零星入库改价会同步指向该入库行的退货单（零星退货 / 采购退货）：草稿直接改价，已过账按补价同一套「原地改流水单价 + 从该位置重算后续」，与采购单改价同步下游一致。
- 采购入库单价仍由采购单回填、只读，不参与更正改价。
- 普通已过账单据仍然不能在编辑页改任何内容，只有走「更正」才可改；只改单价、数量不变也算有效更正，不会被「没有改动」拦截。
- 操作员默认既没有 `correct` 也没有 `void`；主管两者都有，可在权限页单独收回其中一项。
- 更正单没有任何改动（行数、每行数量与单价、单头备注全部一致）时会被拦截，避免产生无意义的修订版本。
- 更正号冲突返回 `DOC_NO_EXISTS`；更正重算若导致负库存，整笔回滚并返回 `INSUFFICIENT_STOCK`；并发下原单或更正草稿状态已变化，返回 `DOC_STATE_CHANGED`，同样不落任何改动。

### 10.1 操作后的页面归属

- 确认 / 更正 / 作废完成后按业务归属跳转：采购退货、零星退货回到「退货与退库」对应页签并定位该单，领料退库回到「退货与退库 · 领料退库」，正常入库 / 出库回到各自模块的详情页。
- 更正产生新单号时定位到更正后的新单；只作废（无新单）时定位到已作废的原单。
- 明细行的删除动作在界面上统一称「移除」，不再出现「删除行」；整单删除仍称「删除」。

### 10.2 主题与语言切换

- 切换深色 / 浅色主题只改配色并就地刷新图表颜色，不重渲染页面，正在编辑的单据、已选详情与滚动位置保持不变。
- 切换中英文需要重渲染文案，但会先保存当前页、子视图（新建 / 编辑单据）与已填表单值、滚动位置，渲染后原样恢复；入库、出库、采购、盘点的编辑页不会被跳走，已填内容不丢。
- body 级弹窗不参与重渲染，已填值保留，但弹窗内文案需重新打开后才会更新为新语言。
